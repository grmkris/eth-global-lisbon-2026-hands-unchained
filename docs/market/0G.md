# 0G — Best AI Product (Proof of Hands market layer)

**Track:** Best AI Product on 0G. **The product:** a robot-teleoperation
labor market whose **neutral referee runs on 0G Compute** — the platform's
pre-existing hole was that operators self-declared success by clicking ✓;
the market cannot trust workers to grade their own paid work. The TEE-backed
grader is load-bearing, not decorative: it decides payments AND slashing.

## Proof inference runs on 0G Compute

`apps/web/src/market/grader/zg.ts` (Direct SDK,
`@0gfoundation/0g-compute-ts-sdk@0.9.0`). Every grade persists this artifact
on the ledger row (shown on the `/market` dashboard, hashed into the HCS
digest):

```json
{
  "chatID": "<ZG-Res-Key response header>",
  "providerAddress": "<ZG_PROVIDER>",
  "model": "qwen/qwen2.5-omni-7b",
  "teeVerified": true,
  "requestHash": "sha256(request body)",
  "responseHash": "sha256(response body)",
  "ts": 0
}
```

`teeVerified` is the boolean from `broker.inference.processResponse()` — a
**TEE-attested signature over the response** (we deliberately do not claim
"proof the model ran"). `null` means no chatID header → unverified, which is
recorded as such, never hidden.

**Grading is telemetry-based by design**: the hub observes duration,
commanded motion (input plane — unforgeable by the operator), gripper
cycles and whether the rig actually saved a LeRobot episode; the model
judges whether the trajectory looks like real work. For a robot data market
this is more defensible than frame captioning — and immune to provider-
catalog churn.

Fallback chain (an 0G outage can never break the loop, only weaken the
artifact): `GRADER=zg` → `zg-router`
(`https://router-api-testnet.integratenetwork.work/v1`, key from
pc.testnet.0g.ai) → `local` heuristics, each failure logged on the row as
`local(fallback:zg-error)`.

## The attestation is verified on ANOTHER chain

The strongest claim in this project: **a Hedera contract cryptographically
verifies that a grade came out of 0G's TEE.**

0G's broker signs every response inside the enclave using plain EIP-191
`personal_sign` over an ASCII string:

```
"<sha256(request)>:<sha256(response)>:<providerType>:<providerIdentity>:<tlsFingerprint>"
```

That is standard secp256k1 over a keccak digest, so *any* EVM chain can check
it with `ecrecover`. `contracts/TeeAttestation.sol` (deployed on **Hedera**
at [`0xE6ad861D…673CC3`](https://hashscan.io/testnet/contract/0xE6ad861D1c18d2FeFe18b49bCa1B407587673CC3))
rebuilds the signed string from the raw response bytes we pass as calldata —
which is what binds the signature to *this* verdict rather than some other
call — and recovers the signer.

Hedera cannot read 0G's registry, so `zgSigner` is pinned at deploy. It is
not guessed: `scripts/deploy-tee-attestation.ts` calls
`getService(provider).teeSignerAddress` on 0G's InferenceServing contract
(`0xa79F4c8311FF93C06b8CfB403690cc987c93F91E`, Galileo) and deploys with
whatever 0G itself reports. Anyone can repeat that call to audit the
constant. One auditable constant ≠ a per-verdict oracle.

Prior art for the primitive: 0G's own `InferenceServing.settleFeesWithTEE`
verifies TEE signatures on-chain. Verifying an inference *result* in a
third-party contract, on a different chain, is not something 0G documents —
this appears to be the first.

**What it proves:** this exact grading output came out of 0G's TEE.
**What it does not prove:** what was asked. The signed request hash covers
the broker's rewritten upstream body, which cannot be reproduced off-chain;
and our backend still chooses which graded attempt to submit. Both limits are
in the contract's own doc comment rather than glossed over.

Run `bun scripts/smoke-tee-bridge.ts` to watch it end to end, including a
tampered response being rejected.
